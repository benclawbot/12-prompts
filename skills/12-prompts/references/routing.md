# Framework router

Use **one** framework, unless explicitly asked otherwise. Explicit ID/name takes precedence.

| ID | Framework | Trigger |
|---|---|---|
| 01 | Socratic Problem Framing | Vague or conflicting problem; needs clarification, not immediate solutions |
| 02 | Two-Layer Explanation | Learn a new concept at both intuitive and technical levels |
| 03 | Reverse-Engineer an Example | Analyze a real artifact and extract transferable techniques |
| 04 | Historical + Competitive Research | Map an unfamiliar domain across time, competitors, scenarios |
| 05 | Claim Verification | Check a factual claim, misleading argument or disputed evidence |
| 06 | Complementary Expert Lenses | Navigate multi-disciplinary tensions and perspectives |
| 07 | First-Principles Redesign | Rebuild a broken or patchwork system from constraints |
| 08 | Cross-Domain Transfer | Find a mechanism from other industries for a stuck problem |
| 09 | Fair Comparison of Two Options | Decide between competing alternatives or courses of action |
| 10 | Minimum Viable Experiment | Test an uncertain idea with a low-cost, reversible pilot |
| 11 | Evidence-Based Strengths Discovery | Investigate personal strengths using concrete examples |
| 12 | Three Possible Futures | Explore several plausible life or career trajectories |


## Collision rules

1. **Direct answer first:** Routine requests, straightforward definitions and explicit artifact requests should receive a direct answer, not a ceremony. If user requests a specific framework, use it.
2. **Verification beats research** when the core request is whether a stated claim is true (05); domain orientation or competitive landscape defaults to 04.
3. **09 vs 10:** If deciding between alternatives, use 09; if ready to test an assumption, use 10. If user asks "how can I tell which is better?", lean 10 when an experiment can resolve it.
4. **07 vs 08:** Derive a new design from real constraints (07) vs borrow analogous mechanisms (08).
5. **01 vs 06:** If the problem itself is unclear, first clarify (01); if multiple disciplines or constraints conflict, use 06.
6. **11 vs 12:** Evidence of personal competence and energy patterns (11) vs design alternative futures (12).
7. If the user supplies an actual artifact for analysis, prefer 03 over speculation about why it is successful.
8. Never pretend the deterministic router table itself proves a choice was correct. When unclear, choose the most useful method and state it briefly.

## Selection output

When a framework adds value, begin with `Framework NN — Name` (or a short natural equivalent), then run it. Do not restate this routing table or print all 12 options. If explicit selection is invalid, ask for a valid number or infer from the described task.
